## 새로운 요구사항

| 유형 | 형식 | 예시 |
| --- | --- |----|
| 고정요금 방식 | A초당 B원 | 10초당 18원 |
| 시간대별 방식 | A시 ~ B시까지 C초당 D원 <br> B시 ~ C시까지 C초당 E원 | 0 ~ 19시 10초당 18원 <br> 19 ~ 24시 10초당 15원 |
| 요일별 방식 | 평일에는 A초당 B원 <br> 공휴일에는 A초당 C원 | 평일 10초당 38원 <br> 공휴일 10초당 19원 |
| 구간별 방식 | 초기 A분 동안 B초당 C원 <br> A분 ~ D분까지 B초당 D원 <br> D분 초과 시 B초당 G원 | 초기 1분 10초당 50원 <br> 이후 10초당 20원 |

**부가 정책에 대한 요구사항은 변하지 않는다.** 부가정책은 여전히 0개 이상, 임의의 순서로 기본정책에 적용될 수 있어야 한다.

- 새로운 요구사항 4가지 방식을 보고 변하는것과 변하지 않는것을 나열
  - 변하는 것
    - 계산 방식
    - 요금 규칙
    - 초당금액
  - 변하지 않는 것
    - 전체 요금 계산 방식
    - 요금제
    - 부가정책
    - 퍼블릭 인터페이스
    - 초당
- 공통으로 가지는 구조가 있다면 설명
  - calculateFee
  - 초당 금액
  - 특정 시간별 금액
  - 요금제 + 임의의 부가정책

새로운 요금제 구현 방식
1. BaseRatePolicy를 상속 한다
2. calculateCallFee 를 오버라이드 한다
3. 필요한 상태 amount, seconds 등을 선언한다
4. calculateCallFee에서 받은 Call을 사용해 시간대별 Call 금액을 계산한다

-------

시간대별 요금제
1. 통화 시간을 받는다
2. 시간대별 계산기 목록을 순회한다
3. 각 시간대별 계산기는 통화시간을 자정기준으로 나눈다
4. 나뉜 통화 구간마다 자기 시간대와 겹치는 구간을 계산한다
   1. 통화 시작 시간과 요금 시간대 시작 시간 중 더 늦은 시간을 선택한다
   2. 통화 종료 시간과 요금 시간대 종료 시간 중 더 이른 시간을 선택한다
   3. 시작 시간이 종료 시간보다 같거나 늦으면 0원을 반환한다
   4. 겹치는 시간이 있으면 해당 구간의 초를 계산한다
   5. 계산된 초를 요금 단위 초로 나눈다.
   6. 시간대별 금액을 곱한다.
5. 시간대별 계산기에서 나온 금액들을 모두 더한다.
6. 최종 요금을 반환한다

요일별 방식
1. 통화 시간을 받는다
2. 통화 시간을 자정 기준으로 나눈다
3. 나뉜 각 통화 구간의 요일을 확인한다
4. 해당 요일에 맞는 요금 규칙을 선택한다
   1. 평일인지 공휴일인지 판단한다
   2. 맞는 요금을 적용한다
5. 각 구간의 통화 시간을 초로 계산한다.
6. 초를 요금 단위 초로 나눈다.
7. 요금을 곱한다.
8. 모든 구간의 결과를 더한다
9. 최종 요금을 반환한다.

구간별 방식
1. 통화 시간을 받는다
2. 통화 전체 시간을 초로 계산한다
3. 통화 시간을 구간 기준으로 나눈다.
   1. 0분 ~ A분 구간 시간을 계산한다.
   2. A분 ~ D분 구간 시간을 계산한다.
   3. D분 초과 구간 시간을 계산한다.
4. 각 구간 시간을 초로 계산한다
5. 초를 요금 단위 초로 나눈다
6. 요금을 곱한다
7. 모든 구간의 결과를 더한다
8. 최종 요금을 반환한다

기존의 Calculator의 책임을 확실하게 분리하고
변하지 않는것과 변하는것을 구분지어
변하는 것을 추상화 시킨다.

초당 금액 이라는 규칙은 변하지 않는다.
조건은 변한다.

정책은 BasicRatePolicy 하나를 사용하며 인스턴스 변수를 List<FeeRule> 로 변경시켰다
- A시부터 B시까지 초당 얼마인지를 포함하고있는 FeeRule

`BasicRatePolicy`에서 계산하는 흐름
1. `feeRule.calculateFee(call)` 이라고 요청을 보내면 FeeRule이
금액을 계산하는데 `FeeCondition`에게 조건에 맞게 구간을 나누라고 요청을 보낸다.
   1. `FeeCondition`에서 구간에 맞게 분리하고 각 방식에 맞는 로직으로 계산한다.
2. `FeeCondition`에게 받은 `intervals` 리스트를 반복시킨다.
   1. `interval`를 초로 변환한다.
   2. 규칙에 맞는 초로 나눈다.
   3. 규칙에 맞는 금액을 곱해 금액을 산출한다.
3. 계산해서 나온 금액을 result에 더해준다.
4. 모든 구간의 금액을 더한후 반환한다.

이과정은 모두 동일하고 변하는건 조건을 설정해 주는 것

각 방식에 맞는 조건을 구현한 `FeeCondition`의 구현체들을 만든다.

`FeeCondition`의 구현체들은 각 조건에 맞는 인스턴스 변수를 보유하며
`findIntervals` 메서드 안에서 조건에 맞는 로직을 구현한다.

변하는 조건을 추상화 하고 변하지 않는 규칙을 하나로 합쳤다
`FeeCondition`에서 어떻게 나누는지는 캡슐화 되어있어 `FeeRule`은 모르는 상태로
계산이 가능하다.
